# Plain-Language Git Glossary

Use these substitutions when narrating steps to a non-technical user. Lead with the plain phrase; the git term can follow in parentheses for their own future searching.

| Git term | Plain-language explanation |
|---|---|
| Repository (repo) | The project's whole folder of files, plus its full history of saved versions. |
| Remote | The address of the copy of the project stored on GitHub's servers, separate from the copy on this computer. |
| Commit | A saved snapshot of the project at this moment, with a note describing what changed. |
| Push | Sending your saved snapshots from this computer up to GitHub. |
| Pull | Bringing snapshots down from GitHub to this computer. |
| Staging | Choosing exactly which changed files go into the next snapshot — like putting items in a box before sealing it. |
| Upstream | The specific place on GitHub that "push" and "pull" talk to by default, so you don't have to specify it every time. |
| Clone | Making a full copy of a GitHub project onto a new computer. |
| Branch | A separate, parallel line of work that can be merged back in later — most small projects only ever use one, called "main." |
| Credential manager | The part of Windows that remembers your GitHub login so you're not asked to log in every single time. |
